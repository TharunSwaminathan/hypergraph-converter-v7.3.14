## Pre-fix reproduction

At authoritative parent `39037cb7b4fdce1f027c8cdd961a48a8ca173288`, the exact request `I did not ask you to delete anything; tell me whether h1 exists.` incorrectly received graph-edit authority, compiled into a graph-mutation plan, reached the protected graph-mutation handler once, and staged one confirmation. The committed graph did not change only because the action remained pending. Permanent pre-fix evidence was committed separately at `993a59ce6e68e4fbf28fdf19b855f0ab714e5567`.

## Root cause

Clause segmentation already separated the two propositions. The semantic defect was downstream: the first clause's negated request speech act was not recognized, so the embedded mutation verb `delete` survived as an affirmative action candidate. The generic fallback then granted `graph_edit_preview`. The second clause's imperative information frame, `tell me whether`, was also not recognized as read-only. Together those gaps allowed the compiled plan to pass the final authorization gate.

## Semantic correction

The repair is clause-local and compositional. It recognizes negated ask/tell/request/instruct/direct/authorize/approve/consent speech acts, related no-permission/no-consent propositions, and `tell me whether/if/...` read-only frames. It denies only the proposition governed by the no-consent construction, so a later fresh directive such as `delete h1 now` remains eligible for the protected preview/confirmation flow. A safe, known-domain state-change mention that does not compile is represented as a `GroundedQuestion`. No global-negation switch or exact-request deny rule was added.

The exact request now has no mutation authorization scope, reaches the graph-mutation handler zero times, stages no confirmation, and leaves graph state unchanged. A forced hostile graph-mutation reattack using the read-only semantics is also blocked by the final side-effect gate.
