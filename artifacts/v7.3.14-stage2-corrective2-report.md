## Corrections

- The CSV row-hypergraph, Incidence, and CSR/CSC CSV routes now share one quote-state-aware full-line comment masking path.
- Strict RFC parsing remains in parseCsvDocument and is unchanged. A # line inside a multiline quoted field remains data; inline # text is not treated as a comment.
- The syntax scanner now tracks whether RFC quote placement is lexically valid as well as balanced. Only valid RFC quoting protects payload from H2H structural detection.
- If RFC quoting is invalid or unclosed, Auto Detect checks the comment-masked raw text for a credible source-colon/neighbor shared clause. Malformed CSV with no credible H2H signature remains CSV and receives the strict RFC diagnostic.
- expH2HResult provides a structured result with ok, text, reason, and assessment. expH2H remains a backward-compatible string wrapper.
- Identifier-unrepresentable H2H keeps its explanatory preview, but both the ordinary UI handler and agent download action return before invoking the downloader. The failure result has no fake filename.
- Existing over-budget/non-computed H2H projection diagnostics remain separate from identifier-representability refusal.

## Successful H2H export invariant

Every H2H identifier class accepted by expH2HResult is tested through:

canonical graph → buildH2H → expH2HResult → autoDetect → parseInputFormat(h2h) → semantic comparison.

This includes balanced, unmatched, and internally balanced literal quote characters; reserved names; commas; internal spaces; and the previously characterized representable delimiter subset.
