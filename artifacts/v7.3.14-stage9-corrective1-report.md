## S9-N01 reproduction and test-first evidence

The defect reproduced exactly. Two Windows package runs were identical at `475f9eaa0549500bbc07b6aa823507899f810be0ecef70f5de834f45001da3b2`; two WSL/Linux runs were identical at `a95303f10f976bdc11c58a4e50fb498f2a53f2edbca1f216b164eedb413a3944`. Both archives were 1,194,025 bytes with 655 members. Member content and metadata matched, but file member ordering differed because `sorted(root.rglob("*"))` compared concrete host-flavor `Path` objects.

Before the production fix, `tests/portable-zip-paths.test.mjs` was expanded with the requested mixed-case corpus. It demonstrates the `PureWindowsPath`/`PurePosixPath` ordering difference, asserts one canonical normalized representation for Windows- and POSIX-spelled paths, and failed because the packager lacked a host-independent key.

## Correction and cross-platform gate

`source_sort_key(path, root)` now returns `path.relative_to(root).as_posix()`, and `iter_source_files` uses that explicit key. Python compares those strings ordinally without locale or filesystem-order dependence. Directory entry names were already normalized POSIX strings and remain explicitly sorted.

Two corrected Windows packages and two corrected WSL/Linux packages all produced the same 1,195,294-byte archive with SHA-256 `e40ae7280476dc6cf59f767e23567db616157c4897095f3ec511f28adfa2747e`. S9-N01 is closed pending independent review.
