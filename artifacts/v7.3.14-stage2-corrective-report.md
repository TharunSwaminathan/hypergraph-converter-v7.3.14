# v7.3.14 Stage 2 Corrective — Quote-Aware Detection and H2H Export Guard

## Scope and checkpoint

This corrective pass is based on immutable Stage 2 commit f2f5da21bee2db4ac4bb0e133779c10e2829de13. It fixes S2-R03A and S2-R03B and characterizes/guards pre-existing S2-N03. It does not amend the Stage 2 commit and contains no Stage 3 work.

## Corrections

- Auto Detect now uses one bounded lexical scan to distinguish H2H structure from text inside RFC-quoted fields. Quote state spans physical newlines.
- The scanner requires a nonblank source before the structural colon and a nonblank neighbor before [shared: ...], or an exact (none) RHS. It does not use exact-phrase exceptions or parse-every-format fallback.
- CSV-route grammar selection now ignores comma and quote punctuation in legacy full-line comments. The same scan masks only comments that begin outside RFC quotes, so a physical line beginning with # inside a multiline quoted field remains payload.
- RFC parsing receives a same-shape comment-masked document. It retains all non-comment data and line endings; no naive line splitting/removal is used.
- The legacy H2H exporter now assesses identifier representability before serialization. Unsafe identifiers return an explicit “H2H export not generated” diagnostic and direct users to H2V or Canonical JSON.

## S2-N03 characterization

The existing H2H grammar has no escaping mechanism. A hyperedge identifier is losslessly representable only when it is non-empty, has no leading/trailing whitespace or line break, does not start with #, and contains neither : nor [. Internal spaces, comma, ], literal quote characters, __proto__, and literal null are supported.

A shared-vertex identifier is losslessly representable only when it is non-empty, contains no whitespace, comma, or ], and—if numeric-looking—imports as a finite numeric token with the identical canonical string. Thus 0, v:1, left[open, literal quotes, __proto__, and null are supported; 007, Infinity, delimiter-bearing, whitespace-bearing, and multiline identifiers are guarded.

The outcome is **GUARDED**, not a grammar redesign. A future explicitly approved H2H format-design stage owns any versioned quoting/escaping syntax and its backward-compatibility tests.

H2H remains projection-lossy by design: it does not reconstruct exclusive vertices or graph metadata. The new guard addresses identifier corruption only.
