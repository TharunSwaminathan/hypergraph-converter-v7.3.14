## Incidence-backed traversal

BFS, DFS, and Connected Components now build one `buildIncidenceIndex()` result per algorithm run. Logical neighbors are generated as the deduplicated union of members in incident hyperedges, excluding the current vertex, and are sorted with default JavaScript string ordering. This preserves the prior traversal-specific ordering contract independently from projection output ordering.

## Projection resource architecture

The bounded projection now reports and separates:

- `candidatePairWork`: every actual candidate encounter; hard limit and preflight policy;
- `uniqueProjectedEdges`: first insertion of an exact unordered pair; hard materialization limit;
- `projectedEdgeSupportReferences`: retained unique supporting-hyperedge IDs; hard storage limit;
- `synchronousWork`: deterministic loop work; separately configurable hard limit;
- `adjacencyReferences`: exact `2 × uniqueProjectedEdges` downstream estimate;
- `renderEdges` and `exportRows`: downstream estimates equal to unique edges;
- `matrixCells`: downstream V² estimate.

Adjacency, render, export, and matrix limits do not become candidate-work preflight limits. `buildAdjacencyList()` enforces adjacency references when it actually creates bidirectional adjacency. Resource refusals expose `exceededResource`, `usage`, `limits`, and a specific reason, and never return a partial projection as successful.

DuplicateOverlap now returns exactly:

- candidate work: 207,000;
- unique edges: 1,035;
- support references: 207,000;
- adjacency-reference estimate: 2,070;
- first-edge weight/support count: 200/200.

Custom gates isolate candidate-work, unique-edge, support-reference, synchronous-work, and adjacency-reference refusal. A 3,000-vertex dense hyperedge still refuses in preflight at 4,498,500 candidate units without exposing partial edges.

## Pair identity and weights

Projection pairs are stored in nested Maps keyed by exact endpoint strings, eliminating delimiter serialization. Numeric-looking identifiers retain numeric primary ordering but use an exact-string tie-breaker when numeric values are equal. Direct tests cover NUL, `"01"`/`"1"`, `"1.0"`/`"1"`, reversed source membership, `"0"`, prototype-like IDs, literal `"null"`, Unicode, and emoji.

A separate 3,000-graph seeded corpus (seed 7,603,220) compared all four weight policies against the pre-change implementation where the old identity was known safe: 12,000 projection comparisons, zero mismatches. Count-shared, sum, minimum, and unweighted policies retain weights 2, 2, 0, and 1 respectively for the zero/two-weight overlap case, with unchanged `h0`/`h1` support metadata.
