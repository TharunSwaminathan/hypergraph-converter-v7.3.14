# Hypergraph Converter Studio v7.3.14 — Stage 4 Corrective Evidence

## Scope and checkpoint

This corrective is descended directly from Stage 4 commit `f08780eaf1320ae7989b00fcd279f6037234b797`. It fixes only S4-N01C, the lack of an exact deterministic tie-break when `localeCompare()` considers two distinct nonnumeric canonical identifiers equal. Stage 5 has not begun.

## S4-N01C pre-fix reproduction

The characterization ran before production editing. In Node v24.19.0, both `"\u00E9".localeCompare("e\u0301")` and `"\u00C5".localeCompare("A\u030A")` returned zero even though each pair contains two different JavaScript strings. With memberships reversed across `h1` and `h2`, each fixture produced two opposite-oriented projected edges, each with weight 1 and one support ID. The machine-readable reproduction is `artifacts/v7.3.14-stage4-corrective-prechange.json`.

## Source correction

The only production file changed is `src/algorithms/projection.js`. Numeric ordering and its existing exact-string tie-break are untouched. Nonnumeric identifiers still use locale ordering first; only a zero collation result for distinct exact strings falls back to JavaScript exact code-unit ordering:

```js
const localeOrder = a.localeCompare(b);
if (localeOrder !== 0) return localeOrder;
if (a === b) return 0;
return a < b ? -1 : 1;
```

No Unicode normalization, lowercasing, trimming, pair-key serialization, or projection weight logic changed.
