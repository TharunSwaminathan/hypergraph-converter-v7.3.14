## Restart matrix: actual behavior, not a promise of tested physical durability

| Event | Current effect |
|---|---|
| Same-owner React rerender | State/refs survive; effects may save updated projection. No new durability guarantee. |
| Ordinary or hard page refresh | Same-origin committed thread/settings/profiles load; graph/uploads/results/pending/actions reset. sessionStorage hint may survive, but authorization does not. Hard refresh does not bypass origin scoping or restore missing graph bytes. |
| Same-origin new tab or reopen | Committed browser data is available to that origin/profile. New owners start empty/unauthorized; a new page session may have no pairing hint. Existing tabs can overwrite shared main snapshots. |
| Browser restart / crash / Windows restart | Browser-managed committed persistent storage may survive if profile/site data is retained. Private-mode, eviction, corruption and crash write loss are not handled as guaranteed backup. No network connection survives process destruction. Physical cases were planned, not executed in this audit. |
| Frontend/application process restart | A still-open tab can retain in-memory state until it reloads. A newly loaded frontend follows the refresh path, provided the same origin is used. No server-owned workspace store is involved. |
| Runtime restart with frontend still mounted | Graph/uploads remain in browser memory. Runtime token/session/job/artifact/result authority becomes invalid; polling or a failed request revokes it. Native pending graph update data can remain in the browser, but old Analyze/Apply binding must be rechecked. |
| Ollama restart with frontend still mounted | Graph/uploads remain. Last connected label can remain during idle until a probe/request detects loss; no periodic App reconnect loop was found. Requests/diagnostics establish errors or a fresh connection. No interrupted generation is resumed. |
| Frontend port/hostname/deployment change | Browser storage namespace changes. Old data remains at its original origin; the new origin sees its own empty/separate stores. No migration path for the full thread/workspace exists. |

## Origin scoping — confirmed functional architecture gap S7-01

The normal combined launcher selects ports 5173–5192 when no FRONTEND_PORT is pinned, sets host 127.0.0.1 and uses Vite `--strictPort`. Explicit FRONTEND_PORT already fails if occupied. Evidence: `run-with-ollama.bat:32`, `run-with-ollama.bat:49`, `run-with-ollama.bat:144`; `run-with-ollama.sh:22`, `scripts/launcher-preflight.mjs:20`. Generic dev/preview launchers also expose other possible host/port choices; they do not define a stable persistence identity.

| Browser URL | Persistence namespace relative to 127.0.0.1:5173 |
|---|---|
| `http://127.0.0.1:5173/` | Original origin; current fixed keys/database. |
| `http://127.0.0.1:5174/` | Different port: separate settings, profiles, thread and pairing-hint storage. |
| `http://localhost:5173/` | Different host: separate storage despite reaching the same computer. |
| `https://hypergraphproject.github.io/hypergraph-converter/` | Different scheme/host/port tuple from local; separate storage. |
| Another path on the same Pages owner origin | Same origin: fixed keys/database can collide/share data across repository paths; paths are not a confidentiality boundary. |

This follows the browser's origin/storage-key model, not just application documentation: [HTML Web Storage](https://html.spec.whatwg.org/multipage/webstorage.html#the-localstorage-attribute), [IndexedDB database isolation](https://w3c.github.io/IndexedDB/#database-construct). Probe P11 checks URL-origin identities and the actual default Runtime allowlist; it is not a browser cross-origin execution test.

Ollama bridge origin configuration follows the selected frontend port. The standard CANDY CLI uses its own default allowlist, which includes local :5173 and one Pages owner, not :5174. Thus fallback can both hide old browser memory and prevent CANDY discovery; these are distinct failures. `run-with-ollama.bat:52`, `candy-runtime/src/cli.js:9`, `candy-runtime/src/config.js:10`. Do not repair this by wildcard origins or trusting remembered connection flags.

## Model reconnection trace

Connect invokes `testConfiguredLocalModel` → `connectOllamaAutomatically`. Attempt order is explicit preference, remembered lastSuccessfulTransport, Direct, Bridge, without duplicates. Direct is `http://localhost:11434`; Bridge is `http://127.0.0.1:<VITE_HYPERGRAPH_BRIDGE_PORT or 8787>/ollama`. Each successful path must list the chosen model and complete the tiny structured-generation check. A missing model or unavailable service fails with guidance; the other configured transport can be tried. No cloud service is introduced. `src/App.jsx:2072`, `src/agent/ollamaConnectionManager.js:14`, `src/agent/ollamaConnectionManager.js:62`, `src/agent/ollamaConnectionManager.js:99`.

“Automatically” currently means selecting/testing a transport during an explicit Connect request, not reconnecting during every startup or after an idle server restart. On a new App mount, stored activeTransport/activeBaseUrl may be displayed as diagnostics, but status is disconnected. A successful new probe overwrites them. Changing bridge port requires matching launcher/build environment; an existing static bundle does not discover an arbitrary new port. Direct/bridge fallback remains bounded to configured destinations. The generic low-level client also permits private-network hosts; ordinary Connect chooses the fixed loopback endpoints. `src/App.jsx:231`, `src/App.jsx:2104`, `src/agent/localModelClient.js:62`.

## Deletion and confidentiality

Clear chat resets displayed messages and conversation memory, then ordinary asynchronous saving updates those portions. It does not erase workspace refs, profiles, settings, pairing storage, Runtime files or downloads. Forget saved workspace references clears the hook reference and may subsequently save the current empty reference projection; it is not a comprehensive privacy erase or a durable deletion receipt. `src/components/AgentChatPanel.jsx:2852`, `src/persistence/usePersistentThread.js:37`, `src/persistence/usePersistentThread.js:40`.

The projector omits a dedicated raw dataset field, but chat/summary/parser strings can themselves contain private data. Ordinary browser storage has no application encryption/redaction/age-based retention layer. Existing safe authority stripping must be preserved while adding user-controlled retention, export and deletion.
