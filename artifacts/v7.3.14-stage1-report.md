# v7.3.14 Stage 1 — Canonical Identity and Result-State Contracts

## Scope

Stage 1 is limited to HG713-C06, HG713-S03, N03, N01, N02, and HG713-R07. No Stage 2 parser/routing/algorithm work is included.

## Established contracts

- Canonical graph IDs are non-empty strings. Finite numeric source IDs remain accepted and normalize to strings, so numeric `0` and string `"0"` denote the same canonical ID.
- Reserved strings (`__proto__`, `constructor`, `toString`), literal `"null"`, Unicode, emoji, negative numbers, and finite floating-point numbers remain valid.
- Explicit null, undefined, blank, arrays, plain objects, booleans, BigInt, NaN, and infinities are rejected as graph IDs. A genuinely missing hyperedge ID retains the existing generated `hN` behavior.
- Duplicate canonical hyperedge IDs are rejected; they are not merged, renamed, or overwritten.
- Visualization node state uses `Map`; the expected-output H2V compatibility object has a null prototype.
- Null and undefined are absence sentinels. They do not compare equal to literal `"null"`; zero remains present.
- `computed` derived results require a present value. Existing `over_budget`, `not_requested`, and `error` status strings remain compatible, with explicit aliases for resource-limited and failed states and a new `invalid_input` state available for later bounded computations.
