# Scope 4B2 architecture decision

Baseline: `592c91f938675d6c76d3179b080c95ed6e1b9398`, branch `candy-integration-scope4b2-cuda-incremental`. Scope 4B1 tag remains `a27eb1246e342097de448408ffa0a4775545c4ae`. Starting Git checks passed with a clean tree and all five protected tags unchanged.

Implementation is additive: a separate C++17/nvcc executable and standalone JS qualification transport. Qualified STATIC production sources and validators remain unchanged. Generic native helpers and mathematical classifier/row-merge logic are copied only from project-owned Scope 4B1 source, with no upstream archive access.

The JS transport first bounds/canonicalizes the old DynamicHypergraph, then invokes the unchanged qualified update adapter. The adapter alone derives the new graph under DELETE_THEN_INSERT semantics. Deleted semantic IDs determine old affected indices; inserted IDs determine new affected indices, including replacements. Typed semantic keys define a common vertex universe and common edge tags, so unchanged incidence can be compared despite dense-index remapping. Declared isolates are retained by the adapter; new-only vertices are harmless isolates in the old packed common universe.

Native input is strict ordered token transport with two canonical H2V snapshots, strictly increasing semantic edge tags and affected indices. The native parser independently verifies that the unaffected tagged edges and memberships are identical across snapshots; affected sets cannot omit changed incidence. A SHA-256 digest binds the entire payload (including graph refs, update identity, snapshots, affected sets, device and declared candidate counts). This is integrity/binding, not authentication: the local operator and JS adapter are trusted semantic authority.

Host candidate generation visits each i<j<k tuple once and retains it iff at least one member is affected. It generates indices only, never region masks or motif counts. Uniqueness follows from the loop structure; candidate cardinality is independently checked as C(n,3)-C(n-a,3). Each GPU kernel classifies only retained candidates. The old/new affected histograms use exact uint64 atomics; checked int64 subtraction produces signed deltas. Unaffected triples cancel, including the permanent shared-anchor counterexample. Production does not invoke STATIC or CPU counting.

The result is delta-only, with old/new affected histograms and candidate/affected counts, bound graph refs, update ID/digest and CUDA metadata. No prior full-count state is accepted or invented, and no full new histogram is claimed. The external harness reconstructs old+delta=new using independent CPU and CUDA_STATIC authorities. Stale prior-count fields are forbidden. Replay against a different version/update digest fails; identical retries are deterministic and do not mutate persistent state. There is no property store or persistent replay ledger in this standalone scope.

Both snapshots keep Scope 4B1 limits: 256 declared edges, 100000 incidences, 5000000 full-snapshot membership visits, and 1000000 vertices. Nonempty edges imply at most 216 realizable edges. Packed bytes are limited to 2 MiB; per-snapshot candidate count is at most C(256,3)=2763520, with both candidate buffers bounded to 66324480 bytes in total. Parsing and allocation arithmetic are checked before launch. No caller candidate tuples, executable, flags or output path are accepted.

Requests use a single bounded descriptor with O_NOFOLLOW/O_NONBLOCK and regular-file verification. Success requires actual CUDA launch and synchronization even for zero candidates; failures emit no partial histograms. Four trusted compile-time fault executables are separate from production. No Runtime Companion, REST, capabilities, browser, UI, ReAct, Ollama, adaptive selection or Scope 4C work is included.
