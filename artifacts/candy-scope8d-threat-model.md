## Overview

Hypergraph Converter Studio is a browser workspace for graph operators. Local Vite and static Pages builds mount `WorkspaceExperience`, which binds the App to a selected project and generation. The store verifies persisted history and the history coordinator publishes only the current owner's snapshot. The Algorithms panel receives that snapshot and scoped existing handlers. The proposed feature derives a list from that snapshot. Existing imports and explicit actions cross different boundaries and remain independent.

## Trust boundaries and assumptions

Assets include the project owner/revision, retained result integrity and provenance, replay ledger, query confidentiality, existing graph/source/memory, durable reconnect intent, import/export destinations, pending confirmations and native tokens/jobs. An external author controls bytes and admissible descriptive claims in a file, including recomputable integrity hashes. An operator controls their local query text. A legitimate same-origin tab may publish an intervening write while another tab has a stale snapshot. None of those capabilities grants a different browser origin, an approved mutation, a Runtime token or operating-system privilege. Code already trusted by the same origin has browser storage access by design. The application manages logical project associations inside that principal.

Scope 7A documents the canonical origin accurately. The README still implies fallback when 5173 is occupied, but combined Windows and Bash launchers fail unless the operator chooses an available explicit port. This is a confirmed documentation discrepancy. Different origin can look like data loss because it opens a different store. Actual hosted origin, browser policy, local operator configuration, profile eviction and OS/host guarantees remain environmental assumptions. HTTPS/loopback secure context behavior matters to Web Crypto (`src/persistence/workspaceProvenance.js:13–15`). Authority-facing qualification remains separated from any live privileged hardware execution.

## Severity and observed results

Critical would require proven exposed code execution or equivalent system/authority takeover. High would require a credible unauthorized sensitive data or durable mutation route, or associated execution capability. Medium requires material integrity/privacy impact reachable under realistic prerequisites. Low covers narrower evidenced security effects. Missing optional functionality, baseline empty copy and stale port documentation do not meet those criteria. No confirmed scoped Critical, High, Medium or Low security finding was established. See D-01/D-02 in the gap register for reproducible source observations. Proposed behavior, production browser timing and environmental boundaries still require qualification.
