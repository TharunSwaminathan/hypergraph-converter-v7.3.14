# v7.3.14 Stage 2 — Parser and Auto-Detection Correctness

## Scope and checkpoint

Stage 2 is based on approved Stage 1 corrective commit `1c2f8e5fbb030d22c0728e29fef123b519c04b18`. It repairs HG713-R03, HG713-C07, HG713-C08, and the coupled Auto Detect behavior. No Stage 3 work is included.

## Corrected contracts

- The existing `csv` public route keeps historical compatibility while dispatching internally to distinct whitespace-row and RFC CSV grammars.
- The built-in whitespace example now yields 3 hyperedges, 5 vertices, and 9 incidences.
- RFC CSV continues to support quoted commas, escaped quotes, embedded newlines, CRLF/LF/bare CR, and strict malformed-quote rejection.
- Incidence metadata distinguishes omitted values from explicit values, including explicit weight 1, and rejects conflicting time or weight with both source rows in the diagnostic.
- H2H accepts only `(none)` or fully consumed comma-separated `neighbor[shared: ...]` clauses. It preserves supported exporter IDs without synthesizing an `h` prefix.
- Adjacency accepts `source: neighbor ...`, permits whitespace/comma neighbor separators, deduplicates reciprocal/duplicate pairs, preserves self-pairs, and rejects missing/extra colons or an empty neighbor list.
- Auto Detect evaluates all relevant row widths, uses RFC-decoded header/signature evidence for comma formats, recognizes H2H markers anywhere in the input, and never uses parse-until-success fallback.
- Structured parser outputs use exact canonical validation at the app commit boundary; the default raw/text cleanup contract remains unchanged.

## Newly confirmed pre-existing defects

- `S2-N01` — RFC-decoded quoted whitespace was discarded downstream by row-hypergraph and incidence parsing/canonicalization. Fixed with exact structured-payload validation and regression coverage.
- `S2-N02` — H2H import stripped and synthesized `h` prefixes, corrupting exporter IDs. Fixed with exact supported textual IDs and round-trip coverage.

H2H remains intentionally projection-lossy: it cannot reconstruct exclusive membership or metadata, and its unescaped shared-vertex list does not represent every possible delimiter-bearing vertex ID. No exporter syntax redesign was attempted.

## Ambiguity decisions

- All-two-token whitespace documents retain Edge List precedence because canonical output is equivalent. Mixed widths use the legacy row-hypergraph parser.
- Headerless Incidence auto-detection requires repeated hyperedge-like first-column evidence; ambiguous normal comma rows remain CSV and can be routed explicitly.
- `h1: garbage` retains Simple/H2V precedence because it is valid Simple syntax. Inputs containing `[shared: ...]` or the exporter `(none)` marker route to strict H2H validation.
- `A:` is invalid because the adjacency adapter emits pair hyperedges and the canonical graph has no isolated-vertex representation.
