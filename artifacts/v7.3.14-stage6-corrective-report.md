## Root cause and correction

`buildAlgorithmIncidenceIndex` described a finite-number compatibility adapter but implemented unrestricted JavaScript `String` coercion and algorithm-local hyperedge-ID synthesis. `shortestPath.js` independently used unrestricted `String` coercion for start and non-null target queries.

The correction is deliberately narrow:

- `src/algorithms/algorithmIncidence.js` now applies the authoritative `normalizeGraphIdentifier` helper to each explicit hyperedge ID and graph member;
- finite numbers still normalize to their string form;
- structured strings remain byte-for-byte/exact-code-unit unchanged;
- unsupported values and blank strings fail before JavaScript coercion;
- missing/null hyperedge IDs are rejected rather than synthesized;
- metadata, weight, time, and attributes are preserved;
- normalized records still flow through the unchanged Stage 3 `buildIncidenceIndex`, including its duplicate detection and read-only topology;
- `src/algorithms/shortestPath.js` uses the same helper for the required start and every non-null target;
- null/undefined targets still mean no target, while a literal `"null"` remains an ordinary vertex ID;
- valid-but-unknown string starts retain the established empty/unreachable result.
