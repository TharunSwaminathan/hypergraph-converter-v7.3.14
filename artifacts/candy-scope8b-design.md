# Scope 8B design and qualification contract

Baseline f1e040e90764eac925d04c78d734a884dc4cd6cc. Design follows the pre-implementation flow map and independent read-only architecture review. Scope is six existing CPU algorithms and validated STATIC/INCREMENTAL motif completions. Automatic statistics, parser proposals, chat/model conversations and unfinished/failed analyses are not archived as successful analyses.

## Data and completion identity

Use an explicit schema-v1 plain-data result record with secure local operation UUID, owner project UUID, start/completion times, canonical algorithm/label, bounded normalized parameters, actual consumed input SHA256, graph identity/version/type/fingerprint, preview marker, available workspace publication revision, project revision at capture, backend/safe runtime-device facts, normalized outcome, outcome digest, origin/provenance and full-record digest. CPU Map values become tagged entry arrays; nonfinite distance values are explicitly tagged. Lazy animation traces/callbacks are excluded, while the displayed final outcome is preserved. Unsupported prototypes/accessors/functions fail; no arbitrary serializer executes user getters. Native history retains data/counts/digests, not registry authority, bearer tokens, client URLs, remote handles or callbacks.

CPU history is generated only for a fresh explicit Run intent and the exact input/options captured by that intent. Existing automatic live recomputation stays live-only. StrictMode/render replay is deduplicated both in the completion observer and durable ledger. Motif completion is observed only after existing registry validation; repeated openResult for the same authorized operation uses the same local completion identity. Intentional rerun always allocates a fresh operation UUID.

History is evidence, not a signature of execution. Imported records are revalidated/rebased to the new local owner and labeled imported/unverified. Self-consistent hashes cannot prove a claimed backend actually ran. Current equivalence is recomputed against actual current input bytes, never trusted from a stored flag. CPU preview input is identified separately from committed graph authority. Source identity is nullable where not captured truthfully.

## Storage / revisions / retention

Add one project-keyed analysisHistories store through an additive IndexedDB version upgrade. An independently validated/digested envelope carries bounded records and a private completion ledger. Each append or reviewed delete/clear advances the shared project revision atomically with history. Exact project CAS and current-owner predicates prevent foreign-tab overwrite; a stale append reports conflict and requires explicit reload. It never silently rebases foreign authority. Own queued chat/workspace/history writes retain the qualified serialized writer lineage.

Duplicate operation/content delivery is a no-op with no new durability claim or writer rebase. A repeated operation UUID with different content fails. Deleted/evicted completion IDs remain in a bounded ledger so late callbacks cannot resurrect records. Project lifetime ledger exhaustion reports LIMIT, rather than silently forgetting replay protection. New intentional operations have new IDs.

Initial policy: at most 24 retained entries, 256 KiB per record, 2 MiB per project, 512 completion IDs and 8 MiB total history. Evict oldest completed records deterministically by completion timestamp then UUID until both retained count/byte budgets fit; never evict workspace or memory. History and existing workspace accounting also share the 128-MiB application workspace/history cap. Clear/delete retains the local completion ledger; whole-project deletion removes that project's history and leaves its identity tombstone. Workspace-only clearing retains historical evidence, which becomes stale/unknown against absent input.

Prepare hashes/normalization outside native transactions; recheck exact project/history snapshot before writes. Resolve saved receipts only on transaction completion. Analysis completion and history persistence have distinct UI states. Quota/serialization/CAS errors preserve existing data and report history unavailable/not saved; no fake receipt. Project switch/unmount abandons obsolete completion writes; restart never resumes pending computation.

## Portability and UI

Keep manifest v2 for history-free exports to preserve Scope8A behavior. Add explicit manifest v3 when safe history is present; accept v1/v2 with empty history and v3 with strict history validation. History joins the existing atomic import transaction and explicit replacement review; unrelated projects/global model intent remain intact. Portable records exclude the local private dedup ledger. Imported records are historical-only, marked imported/unverified and re-sealed under the local owner. A genuine pre-Scope8B export is a required compatibility fixture.

Add a separate Analysis history section with bounded summaries, read-only result/provenance inspection, current-input equivalence, history commit status and safe actions. Selecting history never populates live result/controller state. Delete/clear use current, one-use exact-revision review and Cancel-first confirmation. No rename/favorites/pinning now. CPU rerun selects the supported algorithm/parameters and enters a fresh explicit Run on matching current input. STATIC rerun may request the existing current qualified review flow when available; INCREMENTAL requires recreating a current validated pending update rather than restoring an old one. No history action reconnects or launches a runtime/model.
