# Proposed Scope 8D — search and filter retained analysis history

Qualified Scope 8C baseline `339f62c09821a227937ec3eb1653d1e34cbf46e8`, tree `5a90a1bb30fda50c131bc088c2978a4045ba7ce1`. This is a proposed allowlist for separate authorization.

## Objective and workflow

Find a retained result in the active project's existing Analysis history panel. Add one labeled **Search analysis labels** field, a **Backend** selector, an **Origin** selector and **Reset filters**. Keep the existing list order, row identities, explicit inspection and detail display. Show result count and distinguish loading, unavailable, confirmed empty and no matching results. A history-only imported project uses the same controls after normal Resume.

| Contract | Proposed behavior |
|---|---|
| Input and API | Keep the unchanged `AnalysisHistoryPanel({ history, confirm, onRerun, nativeReady })` interface at `src/App.jsx:5587`. Derive a shallow list of references from `history.records` only. Search the already validated display label via a literal case-insensitive substring, trimming leading/trailing whitespace and capping input to 80 UTF-16 code units at the UI and logic boundary. Empty/whitespace is unfiltered. No regex, tokenization, semantic search, outcome flattening or new dependencies. |
| Filters | Fixed Backend choices All, CPU, CUDA_STATIC, CUDA_INCREMENTAL. Fixed Origin choices All, Local, Imported/unverified, using exact `record.provenance.origin` values. Unsupported control values resolve to All. Combine constraints with AND. Use the same reverse retained order as the baseline; do not re-sort by timestamps or deduplicate. Defaults restore the complete retained list. `data-history-count` retains total rather than visible count. No filter may make execution metadata authoritative. |
| Selection | Detail and record-specific buttons are derived only from a visible current record. Keep selected ID when still eligible. Clear when excluded or removed, with no automatic reselection on widening filters or a later refresh. Do not select the first row or run any action from query/selector changes, including Enter. Reset clears the criteria and leaves an eligible existing selection intact. Maintain existing row buttons and `aria-pressed`. |
| Ownership and lifetime | Query, filters and selection are transient React state scoped to the mounted project. `WorkspaceExperience.jsx:88` already keys AppCore by active owner lineage. Also guard the panel's UI state across direct `history.projectId` changes, including null-to-owner, so no old selection/filter can render with another owner's rows. Remount/reload starts at defaults. Hiding the Algorithms tab in the same mounted Scene retains criteria, consistent with the existing tab lifecycle (`src/App.jsx:5532–5534`). Do not add global/page URL, localStorage, IndexedDB, cross-tab sync, model or telemetry state. |
| Empty/failure states | If `status=ready` and total=0, report no retained results. If ready, total>0 and visible=0, report no matching results and retain reset. Loading or failed/stale discovery never implies an empty project. During writes/errors preserve the existing status and any previously verified rows as a view of the loaded snapshot. If displaying their counts, identify them as loaded. Existing recovery and handler errors remain visible. No new storage retry, repair or cleanup path. |
| Concurrent updates | Re-derive from each supplied snapshot, without a second read, asynchronous search, timers or writes. A foreign change is not authority. Existing single-use destructive review continues to bind the actual command, project, owner and revision. Filter reset or change cannot mint, reuse or retarget approvals. The clear action still concerns all retained history, with its existing confirmation, never a hidden bulk-match subset. |
| Accessibility | Associate labels with controls. Use native input/select/button elements in normal tab order. Announce count/no-match politely without moving focus on typing; preserve existing status/error announcements. When a focused result is removed, restore focus to the search input only if the removal lost focus and no confirmation owns it. Keep existing modal Cancel/Escape and focus restoration. Test a narrow viewport, browser zoom, keyboard and focus. |
| Compatibility | No schema, migration, new store, revision, metadata, retention adjustment or change to downloaded bytes. Existing IDB v5 and history/standalone v1 and workspace v1/v2/v3 are supported as before. Search always uses current renderer records, including history loaded from earlier workspaces and standalone imports. Reveal all retained rows by default. |
| Model and native | Filtering operates fully offline, with no new inference request, reconnect, profile read/write, or startup behavior. Durable OFF, project memory rules and consent continue through existing flows. Existing fresh CPU/STATIC rerun and INCREMENTAL current-update requirement remain explicit and independent. No native/CUDA job, token or action is produced by selecting or filtering. |
| Packaging | Provide a new product doc to describe search scope and storage limits. Include the four proposed paths in both frozen source and candidate archive, verified independently against snapshot or committed inventory as applicable. Keep launchers, manifests, dependencies, policy and workflows outside the boundary. |

## Protected dependencies and non-goals

Protection covers App and action controllers, persistence hooks/coordinators/store/schema/IDB, Resume and confirmation, both codecs, all result data and provenance, memory/Assistant and model controls, launchers/origin policy, Runtime/native/CUDA, release workflows, dependencies and the package producer/verifier. APP state is only an existing prop input. No cross-project search, persisted query/favorites, notes/labels, comparison, new algorithms, custom indexing, search over payloads/source/graph/memory, sort controls, retention changes, salvage, or new portability semantics. A separate README/launcher documentation correction is outside this boundary. Any feature needing one of these paths or capabilities must be scoped independently.

The proposed 80-code-unit cap and metadata-only filter dimensions are design choices for review. Required future evidence includes native screen-reader/focus behavior, current-state retention/search responsiveness and existing authority invariants.
