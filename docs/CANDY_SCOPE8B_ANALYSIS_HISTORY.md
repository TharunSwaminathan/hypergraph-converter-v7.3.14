# Scope 8B: durable analysis history

Analysis history is project-scoped historical data. Explicitly running one of the six CPU algorithms archives its completed final outcome, parameters, actual input SHA256, graph identity/revision, completion time and backend. Existing automatic live recomputation does not create history. Validated CUDA_STATIC and CUDA_INCREMENTAL motif completions can archive detached counts/deltas after the existing result registry accepts them. History does not confer native qualification or authenticate a claimed backend.

Open Algorithms → Analysis history to inspect a result. Inspection changes neither graph nor live result. Input equivalence is recomputed from current analysis input bytes; absent, changed or still-hashing input has unknown/different equivalence. CPU preview input is marked separately from committed graph authority. A result's source digest is null when not independently captured. Workspace publication and shared project revisions are distinct provenance fields.

Resume restores the history view, never computation, Apply, parser state, confirmations, model connection authority or native handles. A CPU rerun allocates a fresh operation identity, rechecks current input and selects current supported algorithm/options. STATIC offers the existing current native review path only when available. To reproduce an INCREMENTAL result, create and review a current pending update; the old update is not executable history. No history action starts or reconnects a process.

## Storage and failures

The additive IndexedDB v5 upgrade adds `analysisHistories`; existing v4 data is retained. Schema-v1 records are plain, strictly validated data with result, completion and record SHA256 digests. CPU Maps use `mapEntries`; unreachable distances use `{ "number": "Infinity" }`. Lazy animation steps, functions/accessors, pending operations, endpoints, session/job handles and credentials are excluded. Digests detect corruption, not maliciously rehashed authorship. Imported evidence is always marked IMPORTED/unverified and assigned new deterministic local record IDs and owner.

Each project retains at most 24 results, 256 KiB per record, 2 MiB per collection (including replay ledger), and 50,000 collection nodes, depth 22. Record normalization has 20,000 nodes/depth 12; validation has 30,000 nodes/depth 20; arrays have at most 10,000 entries. Oversized or unsupported outcomes report history not saved while leaving completed analysis usable. Node/depth limits fail closed; they do not trigger workspace or memory eviction.

Append evicts oldest completion timestamp, then UUID, until retained count and bytes fit. A newly appended completion must itself fit and remain retained. Deletion/clear preserves a private ledger of 512 distinct completion identities, so duplicate callbacks cannot resurrect deleted/evicted evidence. When the lifetime ledger fills, new history saving stops with an explicit LIMIT; use a separate project. There is no implicit reset of replay protection. History globally has an 8 MiB cap and shares the existing 128 MiB workspace/history budget. It never evicts workspace or Assistant memory. Pinning, favorites, renaming and unbounded archival are deferred.

Append and reviewed deletion advance the shared project CAS revision. Same-owner writes serialize through the existing session; foreign stale writers must explicitly reload. Delete/clear confirmation captures an exact one-use command, project and revision, including intervening writes by the same owner. Cancellation writes nothing. Whole-project deletion removes only that project's history and retains its project tombstone; workspace-only clearing retains historical evidence; clearing CANDY data removes histories with other scoped application data.

“Analysis completed” and “History persisted” are separate states. Only native transaction completion acknowledges persistence. Serialization, owner loss, quota or transaction abort reports not saved and preserves existing data. A committed write followed by discovery failure still reports committed, requiring a view reload. Killing the browser before publication yields no partial record; killing after native commit but before UI receipt allows recovery of the whole record. Interrupted or failed analysis is not archived as success and is never restarted by Resume.

## Portable workspaces

History-free exports retain the Scope 8A manifest v2 format. Exports containing history use explicit manifest v3; v1/v2 import remains supported with empty history, including the committed genuine pre-8B native-export fixture. V3 extends only bounded JSON node/array admission (120,000 nodes / 10,000 entries); legacy manifests keep their original 70,000 / 1,000 semantic budgets and all existing payload, authority, size and provenance checks. Container size/depth/string limits are unchanged. Export verifies that its output can pass the decoder budgets.

V3 carries safe records with integrity validation, not the private local replay ledger. Import rebases owner and record IDs, retains original source record provenance, clears adoptable local capture/publication revisions, marks imported/unverified and creates local replay protection. Replacement merges retained destination replay guards and fails if full. History joins the existing atomic workspace/source/graph/memory/selection/model-preference publication and stale replacement review. Unrelated projects and global reconnect OFF intent remain protected. A saved workspace root is still required to export; history-only projects can Resume and inspect history but cannot export an absent workspace.

## Qualification boundary

CPU execution and IndexedDB are exercised in isolated native Chrome. Motif transport/result tests declare simulated qualified STATIC/INCREMENTAL responses and unavailable capability; they are not live GPU execution claims. Actual local qwen3:8b continuity is tested separately. No CUDA/Runtime/native code, model authority, package policy or historical Scope 7F evidence is changed. Proposed-source archives are pre-commit snapshots, not commit-bound releases. Exact candidate-SHA CI, package provenance and promotion remain post-commit work.
